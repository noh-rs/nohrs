## プラグインとは何か

プラグインは WebAssembly コンポーネントです。スクリプトでも動的ライブラリでもありません。WIT インターフェースに対してコンパイルされ、ホストはそれをサンドボックス内で、環境的な権限を一切持たない状態でインスタンス化します。ファイルシステムもネットワークもプロセス起動も、許可されるまで届きません。

この設計が、権限モデルを意味のあるものにしています。プラグインは「ホームディレクトリを読めるが読まないと約束する」ことができません。権限を渡さない限り、そもそも到達できないからです。

## 対応言語

インターフェースはコンポーネントモデルそのものなので、WASM コンポーネントにコンパイルできる言語であれば動きます。ホストと同時に 3 つのテンプレートを出す予定です。

## 権限

プラグインが持つ権限は、すべてユーザーが明示的に許可したものだけです。暗黙の許可はなく、許可した事実は記録されます。種類は意図的に少なく、具体的にしています。

| 権限 | 何ができるか |
| --- | --- |
| `fs:read` | ユーザーがプラグインを適用したパスを読む |
| `fs:write` | 同じパスの中に書き込む |
| `process:spawn` | 名前を指定した外部バイナリを実行する |
| `clipboard:read` | 呼び出された時点のクリップボードを読む |
| `net:fetch` | 宣言したホストにだけ接続する |
| `storage:local` | プラグイン単位に閉じた状態を保存する |

見た目の機能に対して過剰な権限を要求するプラグインは、他のどんなプログラムが同じことをした場合とも同じように扱ってください。

## 配布

プラグインは、このリポジトリの `web/content/plugins/` 以下に 1 つの TOML ファイルとして登録します。登録はプルリクエストで、README・ライセンス・スター数・最終コミットといった残りの情報は、ビルド時にプラグイン自身の GitHub リポジトリから読み取ります。

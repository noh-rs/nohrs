# 端末間共有 (P5)

関連: [`launcher-requirements.md`](./launcher-requirements.md) · [`notch.md`](./notch.md) ·
[`persistence.md`](./persistence.md) · [`plugin-permissions.md`](./plugin-permissions.md)

---

## 1. 何を解くのか

同じ人が 2 台以上の端末で nohrs を使うと、**シェルフもクリップボード履歴も端末ごとに別物**です。
片方でコピーしたリンクをもう片方で貼るには、いま自分宛にメッセージを送るか AirDrop で毎回相手を選ぶ
ことになります。

これを「同じネットワークにいる自分の端末どうしで一つにする」機能として定義します。
クラウドに置く同期ではありません — **同期先はサーバではなく、自分のもう一台**です。
この区別が [§9](#9-アカウントと課金) と
[`launcher-requirements.md`](./launcher-requirements.md) §10 の書き分けの根拠になります。

## 3. 譲らない三点

決めごとではなく、実装に入る前に固定しておく線です。ここを曲げる変更は入れません。

1. **サーバは身元を保証するが、中身は読めない。** サーバが持つのは公開鍵の名簿だけです。
   端末間を流れるデータはサーバを通らず、通る将来の中継 ([§5.3](#53-中継-p5-以降)) でも暗号文のまま素通りします。
2. **鍵のピン留めはアカウントより長生きする。** 一度ペアリングした端末どうしは、ログアウトしても
   課金が切れても LAN では繋がったままです。アカウントは繋ぎ方を楽にするもので、繋がりの根拠ではありません。
3. **新しい端末の参加は、既存の端末に出る。** サーバ側の操作だけで端末群に何かを足せると、1 が意味を失います。
   承認は必ず手元の端末で行われます。

## 4. ペアリング

二経路ありますが、**着地は同じ**です — 「互いの公開鍵を覚えている (ピン留めしている)」状態。
違うのはそこに至る手間だけで、繋がった後の動作に差はありません。

### 4.1 アカウント無し (手でつなぐ)

1. 片方で「端末を追加」を開くと、**6 桁のコード**と自分の鍵の**指紋**が出る。
2. もう片方で同じ画面を開き、そのコードを打つ。
3. 両方の画面に相手の指紋が出るので、**同じものが出ていることを目で見る**。
4. 承認すると互いの公開鍵を覚える。以後コードは要らない。

コードは**その場限り・短命**で、指紋の読み合わせは中間者を人間が弾くための手順です。
コードだけで鍵交換を完了させると、コードを盗み見た相手が割り込めます。

### 4.2 アカウント有り (勝手につながる)

1. 両方の端末が同じアカウントでログインしている。
2. 各端末が**自分の公開鍵を名簿に載せる**。秘密鍵は端末から出ません。
3. LAN で相手を見つけたら、名簿に照らして「確かにこのアカウントの端末だ」を確認する。
4. **初回だけ、既存の端末に「この端末を入れていいか」が出る**。承認で完了 (§3 の 3)。

6 桁のコードも指紋の読み合わせも出てきません。**そこがアカウントの価値**です
([§9](#9-アカウントと課金) の有料線引きの根拠)。

### 4.3 指紋が変わったとき

**接続を止めて聞き直します。** 黙って繋ぎ直しません。端末の再インストールで正当に変わることも
ありますが、それを黙って受け入れる実装は中間者も黙って受け入れます。
「この端末の鍵が変わっています」を出し、ユーザーが承認するまで共有を止めます。

## 5. 見つけ方と繋ぎ方

### 5.1 発見

同じ LAN 上で mDNS により名乗り合います。見つけた相手が既知 (ピン留め済み) なら直接繋ぎます。
**mDNS が塞がれている環境**(多くの企業ネットワーク) に備えて、**アドレスを手で入れる口**を残します。
相手がスリープしていれば単に見つからない、という扱いで、エラーにはしません。

### 5.2 接続

TLS で、**サーバ証明書ではなくピン留め済みの公開鍵**で相手を確かめます。公開 CA は関係しません。
実装の候補 (Noise / raw public key の TLS / QUIC) は [R26](#14-未解決--要調査) で、ここでは決めません。

### 5.3 中継 (P5 以降)

LAN をまたぐ中継は**最初は作りません**。作るときも中継は暗号文を転送するだけで、
§3 の 1 を満たさない実装は入れません。有料機能の想定は [§9](#9-アカウントと課金)。

## 6. 何が端末をまたぎ、何がまたがないか

「またがない」の多くは、渡しても**渡した先で成立しない**ものです。技術的に無理なのではありません。

| もの | またぐか | 理由 |
|------|:--------:|------|
| クリップボード | **○** | 既定は最新 1 件。履歴はオプトイン ([§7](#7-クリップボード)) |
| シェルフ | **○** | 一覧は常に、実体は要求されたとき ([§8](#8-シェルフ)) |
| 削除の取り消し | ✕ | 消したファイルはその端末のゴミ箱にしかありません。別の端末で「元に戻す」を押しても**戻す先が無い** |
| ファイル操作の進捗 | ✕ | その端末のディスクの仕事です。別の端末で見えても手出しできません |
| 設定・キーバインド | ✕ | OS が違えば修飾キーも押せる組み合わせも違います。揃えると片方が壊れます ([`launcher-requirements.md`](./launcher-requirements.md) §4.5 の 5.12 は据え置き) |
| プラグインと `plugin_kv` | ✕ | 権限はその端末で許可したものです。**許可ごと別の端末に移る**のは許可の意味を壊します ([`plugin-permissions.md`](./plugin-permissions.md)) |
| ウィンドウ / フォーカス履歴 | ✕ | ディスクにも書きません ([`launcher-requirements.md`](./launcher-requirements.md) §5.11)。別の端末のウィンドウには戻れません |
| ファイルの索引 | ✕ | 相手のディスクの目録です。持っていても開けません |

## 7. クリップボード

### 7.1 既定 — 最新の 1 件だけ (D11)

片方でコピーしたものが、もう片方で**そのまま貼れる**状態になります。
相手の履歴には入れず、**相手の「いまのクリップボード」を差し替える**だけです。

- 送るのは**コピーが起きた端末**から、繋がっている端末へ。
- 受けた端末では履歴に積みません。**積むと「1 件だけ」の約束が崩れます**。
- 大きいものは送りません。上限は [§10](#10-予算) 。超えるものは送らず、送らなかったことを記録します。

### 7.2 履歴モード (オプトイン)

設定でオンにすると、クリップ履歴そのものが端末をまたいで一つになります。
ノッチのクリップ履歴パネル ([`notch.md`](./notch.md) §3.6) が端末を区別せず並べます。

オンにするときは、**何が変わるかを文章で出してから**にします — 「この端末でコピーしたものが、
繋がっている端末すべてに残るようになります」。設定項目の名前だけで済ませません。

### 7.3 除外ルールは送る側で効く

[`launcher-requirements.md`](./launcher-requirements.md) §5.4 の除外ルール
(パスワードマネージャ、`NSPasteboardTypeAutoGenerated` 等) は、**送信を決める時点で**適用します。
受け側で捨てる設計にすると、**捨てる前に一度ネットワークに出ています**。

### 7.4 保持期間

**受け取った側の保持期間で切ります。** 送信元の設定は持ち込みません。
長い方に揃えると、片方の端末を緩く設定するだけでもう片方の契約が破れます
([`migration.md`](./migration.md) の import と同じ考え方)。

## 8. シェルフ

### 8.1 渡るのは一覧だけ (D12)

端末 A がシェルフに置いたものは、B には**名前・サイズ・種類・サムネイル**だけが渡ります。
実体は A に残ったままです。置いただけの大きいファイルが黙って全端末のディスクを埋めることはありません。

### 8.2 実体を取りに行くのはいつか — 先読み

**押し付けではなく取りに行く**のは決定 (D12) ですが、*いつ*取りに行くかは体験を左右します。

| 取りに行く時点 | 何が起きるか |
|--------------|------------|
| 掴んだ瞬間 | **ドラッグの途中で待たされます**。掴んで動かしているのに実体が無い、が一番まずい待たされ方です |
| **シェルフを開いた時点 (採用)** | 人が開いてから掴むまでの数百ミリ秒〜数秒を転送に使えます。掴む頃には手元にある |

先読みでも **A は何も押し付けません** — B が B の判断で取りに行くだけです。一覧しか渡らない原則は
変わりません。無駄が出るのは「開いたが何も掴まなかった」場合なので、歯止めを置きます:

- **LAN でだけ**先読みします。中継越し ([§5.3](#53-中継-p5-以降)) では掴まれてから取りに行きます。
- **シェルフを閉じたら中断**し、取りかけは捨てます。
- **1 アイテムの上限**を超えるものは先読みしません (掴まれてから)。既定値は [§12](#12-設定)。

### 8.3 リモート項目の見え方

- 実体が手元に無い項目は、**手元にある項目と見た目で区別できる**ようにします
  (どの端末のものかを出す)。区別が付かないと、繋がっていないときに掴めない理由が分かりません。
- **取れない状態のものを、取れるように見せません**。相手がスリープしていれば、その項目は掴めない
  見た目になります。

### 8.4 取れなかったとき

掴んだのに実体が取れなかった場合は、**ドロップを失敗として返します**。
空のファイルや途中までのファイルを相手のアプリに渡す方が、渡さないより悪い
([`notch.md`](./notch.md) §3.2 の G と同じ理由です)。

## 9. アカウントと課金

**アカウントは存在しますが、無くても全部の機能がローカルで動きます。**
「アカウント不要」は「アカウントという概念が無い」ではなく、
「**無くても使える**」という意味です ([`launcher-requirements.md`](./launcher-requirements.md) 原則 1)。

| できること | アカウント無し | 無料アカウント | 有料 |
|-----------|:-------------:|:-------------:|:----:|
| 同じ LAN での共有 | **○** 手でペアリング | **○** 自動 | **○** |
| 端末の自動発見・端末一覧・失効 | — | **○** | **○** |
| ネットワークをまたぐ中継 | — | — | **○** |
| つなげる端末の数 | 2 台 | 制限あり | 無制限 |

**解約しても LAN 共有は動き続けます** (§3 の 2)。止まるのは自動発見と中継だけです。
ここを曖昧にすると、ローカルファーストという看板と課金が正面衝突します。

## 10. 予算

| 項目 | 予算 | 理由 |
|------|------|------|
| 共有オフ時の常駐コスト | **0** | 機能を使わない人に負担を出しません。オフならソケットも mDNS も開きません |
| 共有オン・アイドル時 | 常駐 RSS +10MB 以内、アイドル CPU は [`launcher-requirements.md`](./launcher-requirements.md) §6 の予算の内側 | 常駐が重くなるなら共有そのものを見送ります |
| クリップボード 1 件の上限 | 既定 **10MB** | これを超えるものは送りません。貼り付けのために巨大な blob を即時転送する価値はありません |
| 先読み 1 アイテムの上限 | 既定 **50MB** | シェルフの 1 アイテム上限 ([`notch.md`](./notch.md) §3.2) と揃えます |

## 11. セキュリティで守ること

機構ではなく、満たすべき性質として書きます。どう満たすかは [R26](#14-未解決--要調査)。

- **A** 端末間を流れる内容は、**両端の端末以外には読めない**。サーバも中継も含みます。
- **B** ピン留めした鍵が変わったら**繋がない**。黙って受け入れない ([§4.3](#43-指紋が変わったとき))。
- **C** **アカウントの状態が、既にピン留めされた端末どうしの接続可否を左右しない** (§3 の 2)。
- **D** 端末の**追加は手元の承認を要する**。サーバ側の操作だけで増えない (§3 の 3)。
- **E** 共有がオフのとき、**ネットワークに出る処理は一切動かない**。待ち受けもしない。
- **F** 除外ルールに当たったクリップは、**送信の判断より前に落ちる** ([§7.3](#73-除外ルールは送る側で効く))。
- **G** 受け取ったデータは**信用しない**。サイズ・型・件数を、
  [`migration.md`](./migration.md) の import と同じ厳しさで検査してから書きます。

## 12. 設定

```toml
[sharing]
enabled = false            # 既定オフ。オンにするまで待ち受けもしません (§11 の E)
clipboard = "latest"       # "off" | "latest" | "history"  (D11。既定は latest)
shelf = true               # 一覧の共有。実体は常に要求されたときだけ (D12)

[sharing.prefetch]
enabled  = true            # シェルフを開いた時点で実体を取りに行く (§8.2)
lan_only = true            # 中継越しでは先読みしない
max_item_mb = 50           # これを超えるものは掴まれてから
```

端末ごとの表示名と、繋がっている端末の一覧・失効は設定画面から。
**設定ファイルは端末をまたぎません** ([§6](#6-何が端末をまたぎ何がまたがないか))。

# Notch — 3 つ目のサーフェス

> Status: Draft (要件・設計。実装は P4 以降)
> Related: [`launcher-requirements.md`](./launcher-requirements.md) / [`launcher.md`](./launcher.md) /
> [`explorer-essentials.md`](./explorer-essentials.md) / [`os-integration.md`](./os-integration.md) / [`migration.md`](./migration.md)

本書は MacBook の **notch (カメラハウジング周辺)** を nohrs の 3 つ目のサーフェスとして扱うための要件と設計を定めます。
explorer window / launcher window に続く常駐サーフェスで、**「今なにが起きているか」と「一時的に物を置く場所」**を担当します。

---

## 1. なぜ notch を第一級にするのか

notch アプリ (NotchNook / Boring Notch / Alcove など) は現在、**ランチャーとは別プロセスの 4 つ目の常駐アプリ**として
存在しています。nohrs は既に

- 常駐してファイルインデックスを持ち ([`search.md`](./search.md))、
- ファイル操作を実行し ([`explorer-essentials.md`](./explorer-essentials.md))、
- ドラッグ & ドロップの送り手と受け手の両方であり、
- notch の前フェーズ (P3.5) でクリップボード履歴を持つ ([`launcher-requirements.md`](./launcher-requirements.md) §5.4)

ため、notch v1 に着手する時点で、**notch に出したいものをすでに全部持っている**ことになります。
別プロセスを増やさずに出せるのは構造的な優位です。

逆に言えば、nohrs の notch は「メディアコントロールの置き場所」ではなく、
**Explorer × Launcher の常駐面**として設計します。他社の notch アプリが持てないのは次の 3 つです。

1. **シェルフと explorer が同じファイル操作基盤を共有する** (シェルフから explorer へ、explorer からシェルフへ)。
2. **長時間のファイル操作 / インデックス作成の進捗が出る** (コピー・移動・ゴミ箱・プラグイン導入)。
3. **クリップボード履歴とシェルフが地続き** (Supaste の "notch shelf" が単体で売れている領域)。

---

## 2. サーフェスモデル

notch は 4 つの状態を持ちます。状態遷移はすべて**ポインタとドラッグだけ**で完結し、キーボードは補助です。

| 状態 | 見え方 | 入り方 | 出方 |
|------|--------|--------|------|
| **Hidden** | 何も描かない (物理 notch のまま) | 既定 / 設定で無効化時 | — |
| **Idle (pill)** | notch の左右にごく小さいインジケータ。**出すのは「存在」だけで「中身」ではない** ([§3.8](#38-プライバシー)) | 進行中・要確認のことがあるとき、またはシェルフが空でないとき | アクティビティが片付いたら Hidden。シェルフが空でない間は残る |
| **Hover** | notch がひと回り広がり、要約 1 行 + 主要ボタン | ポインタが notch 領域に入る | ポインタが離れる |
| **Open** | パネルが下に展開。タブでシェルフ / クリップ / アクティビティ / ウィジェット | クリック / ファイルをドラッグして notch に近づける / ホットキー | `Esc` / 外側クリック / ドロップ完了 |

**ドラッグ中の特別扱い**: ファイルをドラッグしたまま画面上端に近づけると、Hover を飛ばして Open に直行し、
**複数のドロップ先に展開**します ([§3.3](#33-ドラッグ時のドロップ先ファンアウト-p4))。的に合わせずに離せばシェルフ行きです。
これが notch の最頻ユースケースなので、他のどの遷移よりも速くする。

**notch が自分から Open まで開くのは、このドラッグのときだけ**です ([§3.7](#37-同時に起きたときの捌き方))。
進捗も新着も Idle (pill) 止まりで、開くかどうかはユーザーが決めます。**何も無かったところから**パネルが降りてきて
メニューバーとウィンドウの上端を覆うので、自発的に開くものは「作業を止めるもの」になります。

### 2.1 非 notch マシン / Linux でのフォールバック

notch が無い Mac (Air 2020, 外部ディスプレイ, Mac mini) と Linux でも**同じ機能が使える**必要があります。
無いものを理由に機能ごと落とすと、クロスプラットフォーム原則 (原則 5) が崩れます。

| 環境 | 形態 |
|------|------|
| notch あり (内蔵ディスプレイ) | 物理 notch に重ねる |
| notch なし / 外部ディスプレイ | 画面上端中央に**同じ形の浮遊バー**を出す (Idle 時は数 px の細い帯) |
| Linux (X11) | 同上。`_NET_WM_WINDOW_TYPE_DOCK` + `_NET_WM_STATE_ABOVE` |
| Linux (Wayland) | `wlr-layer-shell` が使えるコンポジタでのみ同等。使えなければ **notch サーフェスを提供しない**と明示し、シェルフは launcher 内のタブとして出す |

**設計上の帰結**: シェルフ / クリップ / アクティビティの**中身のビューは notch 専用にしない**。
launcher のタブとしても、explorer のサイドバーパネルとしても同じビューを出せるようにする
(= `nohrs-ui` のコンポーネントとして作り、`nohrs-notch` はそれを載せる器に徹する)。

## 3. 何を載せるか

### 3.0 判断基準

notch は「小さい画面」ではありません。**普段は何も出ていない**場所です。物理的な notch は常にそこにありますが、
nohrs が描くものは、ポインタを置いて初めて出てきます (§2 の Hidden → Hover → Open)。
この**出方**が、何を載せてよいかをほぼ決めます。

- **一瞥で読めることに価値がある機能は、この出方だと価値が消える。** 時計・天気・バッテリー・システム統計は
  「視界の端に勝手に映っているから意味がある」ものです。ホバーして初めて読める時計は、メニューバーの時計に
  **劣ります**。席が狭いから外すのではなく、**この surface では成立しないから**外す。
- **狙うのに 1 往復かかる。** ポインタを画面上端まで運ぶコストが先払いなので、着いた先が「見るだけ」で
  終わるものは往復に見合いません。だから「そこで何かできる」ことが要る。
- **出てくる瞬間が作業を遮る。** 何も無いところからパネルが降りてきて、メニューバーとウィンドウの上端を覆います。
  z-order 上はどのアプリよりも手前なので、出す判断は保守的にします ([§3.7](#37-同時に起きたときの捌き方))。

他社の notch アプリがウィジェットホスト (天気・時計・統計・ミラー) に寄っていくのは、この席を**表示**に
使っているからです。nohrs は**操作**に使います。

launcher と notch の役割はこう分かれます。

| | launcher | notch |
|---|---|---|
| 起点 | **引く** (pull) — 自分が呼ぶ。何が欲しいか分かっている | **押される / 抱える** (push / carry) — 向こうで何かが起きる。または手に持っている最中 |
| 寿命 | 呼んだ数秒 | 作業の裏でずっと |
| 失敗の形 | 出てこない・遅い | **邪魔** |

そのうえで、notch に載せてよいものは**次の 4 つを全部満たすもの**だけとします。

| # | テスト | 落ちる例 |
|---|--------|---------|
| **T1** | **自分が見に行かなくても起きる** (push)。見に行くものは launcher に置く | 天気・時計・システム統計 — 見たいときに見るもの = pull |
| **T2** | **見て終わりではなく、その場で次の操作がある** (ドラッグ・取り消し・開く・止める) | CPU 使用率グラフ — 上端まで往復した先が「見るだけ」では割に合わない |
| **T3** | **一過性か、携行中か**。常設の表示にならない | カレンダーの今日の予定 — 常設のものは「常に見えている」ことが価値で、ホバーで初めて出る場所とは噛み合わない |
| **T4** | **nohrs しか知らない**、または nohrs が既に持っている情報である | Now Playing・音量・バッテリー — Control Center が 20px 隣で出しており、**しかもあちらは一瞥で読める**。重複な上に劣る |

T4 が効く場面は多く、結果として**メディア・HUD・バッテリー・カレンダー・統計はコアから落ちます**
([§3.10](#310-コアに載せないもの))。これらを欲しい人が居ることは否定しません。置き場所を
plugin にする、というのが答えです ([§3.9](#39-プラグインが載せるもの))。

### 3.2 ファイルシェルフ (P4, 最優先)

**要件**

- 任意のアプリからドラッグしたファイル / テキスト / 画像を**一時的に保持**する。実体は移動せず、パス参照
  (アプリ外から来た生データのみ `$XDG_DATA_HOME/nohrs/shelf/` に退避)。
- シェルフからのドラッグアウトは、**元アプリが期待する形** (`NSFilenamesPboardType` / `text/uri-list`) で出す。
- アクション: explorer で開く / Reveal / まとめてコピー・移動 (explorer のファイル操作基盤を呼ぶ) / AirDrop 送信 (macOS) /
  クリップボードにパスをコピー / 削除 (シェルフからだけ外す) / まとめて zip。
- **explorer 側との往復**: explorer の選択を `Cmd+Shift+S` 等でシェルフに送れる。シェルフから explorer の
  現在ディレクトリにドロップできる。
- シェルフの内容は再起動を跨いで復元する (redb `shelf.items`)。ただし存在しなくなったパスは復元時に落とす。
- **複数の出どころから溜められる**こと。ブラウザから 1 つ、Slack から 1 つ、explorer から 3 つ、と別々に放り込んで
  最後に 1 回で落とす、が主用途です。1 回のドラッグを中継するだけなら、シェルフは要りません。
- **CLI から入れられる**: `noh shelf add <path>...` / `noh shelf list` / `noh shelf clear`。ターミナルで見つけた
  ファイルを GUI のアプリに渡す導線がここで繋がります ([`cli.md`](./cli.md) に追加)。
- **シェルフが空でないことだけは、Idle でも出す**。これは「普段は何も出ていない」([§3.0](#30-判断基準)) の
  **唯一の例外**です。ホバーするまで見えないと、携行していること自体を忘れます — そして忘れたシェルフは
  事故になります (古いファイルを掴んだまま次の作業に入り、意図しないものを渡す)。「そこに何かある」ことは
  ホバー前に分かる必要があり、「それが何か」はホバーしてからで十分です。出すのは**件数だけで、
  中身は出しません** ([§3.8](#38-プライバシー))。設定で消せます。

**受け入れ基準**

- ドラッグ開始から notch が Open になるまで **< 150ms**。
- 100 件のファイルをシェルフに入れても一覧のスクロールが 60fps を維持する。
- シェルフ経由の移動 / コピーは explorer と**同一の** conflict 解決 UI (Rename/Overwrite/Skip + Apply to all) を使う。
- シェルフが空のとき、Idle の描画は**完全に消える** (件数バッジも出ない)。

### 3.3 ドラッグ時のドロップ先ファンアウト (P4)

シェルフ 1 つだけを的にすると、「シェルフに入れてから、改めて行き先を選ぶ」の 2 手になります。
ドラッグしたまま上端に近づいた時点で、notch を**複数のドロップ先に展開**します。

| ドロップ先 | 内容 |
|-----------|------|
| **シェルフ** | 既定。どの的にも合わせずに離したらここ |
| **いま開いている explorer のディレクトリ** | explorer が開いていて、そのディレクトリが書き込み可能なときだけ |
| **最近使ったフォルダ** | launcher と同じ履歴 ([`launcher-requirements.md`](./launcher-requirements.md) §7.5 の `history` テーブル、`kind="open"`) を使う。**残り枠を埋める分だけ** |
| **AirDrop** | macOS のみ。ファイル / フォルダをドラッグしているときだけ |
| **新規ファイルとして保存** | テキスト / 画像など、ファイルでないものをドラッグしているとき |

- 的は**最大 5 つ**。増やすと狙えなくなります。候補が上回るので、**優先順位で埋めます**:
  ① シェルフ (常に出す) → ② いま開いている explorer のディレクトリ → ③ AirDrop または「新規ファイルとして保存」
  (ドラッグしているものの種別で排他) → ④ 残り枠を最近使ったフォルダで埋める (最大 2)。
  ②③ が条件を満たさないときは、その枠も最近使ったフォルダに回ります。
- 各的は「落とすと何が起きるか」を書く (`移動` / `コピー` — 修飾キーで変わるので、キーを押し替えたら表示も変わる)。
- 的の上でホバーしている間は、その的だけを強調して他を沈める。

**受け入れ基準**: ドラッグ開始からファンアウト完了まで **< 150ms**、的の当たり判定は最小 44×44pt。

### 3.4 ライブアクティビティ (P4)

nohrs 自身が抱えている処理を出します。**他アプリの監視はしません** (原則 1: 常駐は軽く)。

| 種類 | 出すもの |
|------|---------|
| ファイル操作 | コピー / 移動 / ゴミ箱 / 復元 の進捗、対象数、残り時間、**キャンセル** |
| **破壊的操作の取り消し猶予** | ゴミ箱 / 上書き / 移動の直後、**既定 10 秒**だけ `取り消す` を出す (下記) |
| **失敗した操作の回収** | 失敗・部分完了の通知と、再試行 / 詳細 / 残骸の場所 (下記) |
| インデックス | 初回スキャン / 再インデックスの進捗、一時停止 |
| 検索 | 長い全文検索の実行中表示 (中断可能) |
| プラグイン | インストール / 更新の進捗 (ホスト側が出すもの)。**plugin 自身が投げるアクティビティは P5** — WIT の `notch` interface がまだ無いため ([§3.9](#39-プラグインが載せるもの)) |

#### 取り消し猶予がここにある理由

explorer の undo は**ウィンドウ単位のスタック**です ([`explorer-essentials.md`](./explorer-essentials.md) §1)。
つまり、ファイルを捨てて別のアプリに移った瞬間、取り消す手段が画面から消えます。**間違いに気づくのは
たいていその後**です。notch はウィンドウより長生きするので、ここが唯一の置き場所になります。

- 対象は破壊的操作 (ゴミ箱 / 上書き / 移動) のみ。コピーや新規作成には出しません。
- 猶予中に explorer ウィンドウを閉じても、タブを閉じても、**猶予は消えません**。
- 猶予が切れたら黙って消えます (「取り消せなくなりました」とは言わない — それは通知の無駄遣い)。

#### 失敗の回収がここにある理由

同じ理由です。`explorer` のステータスバーは、そのウィンドウが開いている間しか読めません。
[`explorer-essentials.md`](./explorer-essentials.md) の「移動しきれず元が残った」系の結果
(部分完了) は、**ウィンドウを閉じた後に効いてくる情報**なので、notch に出口を作ります。

**受け入れ基準**

- アクティビティが無いときは**何も描かず、タイマーも回さない** (アイドル CPU 0 に落ちる)。
- ゴミ箱に捨て → explorer ウィンドウを閉じる → notch の `取り消す` で元に戻る、が通ること。
- 進捗の更新で notch が**自発的に開かない** ([§3.7](#37-同時に起きたときの捌き方))。

### 3.5 見張り (P5)

**新しい常駐ポーリングは増やしません。** ただし出どころは 1 つではないので、種類ごとに分けて書きます。

| 出どころ | 使うもの |
|---------|---------|
| ファイルの新着 (ダウンロード / スクリーンショット) | [`search.md`](./search.md) §6 の watcher に相乗り。監視対象のルートを 2 つ足すだけ |
| ボリュームの着脱 | **OS のイベント**。macOS は `NSWorkspace` の `didMount` / `didUnmount`、Linux は udev / UDisks2。ポーリングではない |
| 空き容量 | **watcher ではなく、コピー / 移動を始める前の事前チェック**。常時の監視はしない (常時見張るなら T2 に落ちる) |

| 見張るもの | 出すもの | なぜ notch か |
|-----------|---------|--------------|
| **ダウンロード先の新着** | 直近の 1-3 件を、**既定 10 分**だけ取り出せる状態で置く。ドラッグで直接アプリへ、クリックで explorer | 「ダウンロード → Finder で探す → アプリにドラッグ」という毎日の 3 手を 1 手にする |
| **スクリーンショット** | 撮った直後のファイルを出す。ドラッグ / 改名 / 移動 / 破棄 | 既定の保存先はデスクトップで、散らかる。撮った直後が唯一「これが何か」を覚えている時間 |
| **ボリュームのマウント / 取り外し** | マウントは `開く` 付き。取り外しは**進行中の操作がそのボリュームを触っているときだけ**警告 | 外付けを抜いた瞬間にコピーが壊れる事故を、抜く前に止められる |
| **コピー先の空き容量** | **足りないときだけ**。開始前に「あと N GB 足りません」 | 常時のディスク表示は T2/T4 に落ちる。足りない瞬間だけは行動がある |

- どの見張りも**個別にオフ**にでき、既定は「ダウンロード」と「スクリーンショット」がオフ、残りがオン
  (前者 2 つはユーザーのフォルダを覗くので、明示的に許可を取ってから)。
- 見張りは**通知を出しません**。notch の Idle 表示に留め、開いたときに読める形にします。

### 3.6 クリップボード覗き見 (P4)

- 直近 N 件 (既定 10) を notch から一覧・貼り付け。Supaste の `Ctrl+Cmd+0-9` に相当する番号アクセスを持つ。
- 機微情報の除外ルールは launcher 側と**同一実装**を使う ([`launcher-requirements.md`](./launcher-requirements.md) §5.4)。
- notch では**中身のプレビューを既定で伏せる**。ホバーで開く ([§3.8](#38-プライバシー))。
- 4 つのテストのうち T1 (push) だけは満たしません。載せるのは、**手がマウスにあるときの経路**として
  意味があるからです (launcher はキーボードの経路)。同じ中身に 2 つの手を用意する、という位置づけ。

### 3.7 同時に起きたときの捌き方

面積が狭いので、「複数のことが同時に起きたらどうするか」を決めていないと、最初の実装で破綻します。

| 規則 | 内容 |
|------|------|
| **同時に見えるアクティビティは 1 つ** | 残りはキューに積み、pill に `+2` のように数だけ出す |
| **優先度** | ① 要確認 (失敗・容量不足・取り外し警告) → ② 取り消し猶予 → ③ 進行中の操作 → ④ 見張りの新着。上が来たら下を押しのける |
| **同種は合流** | コピー 3 件は 3 行ではなく `3 件をコピー中`。合流した行を開くと内訳が出る |
| **自発的に開かない** | notch が自分で Open まで開くのは**ドラッグのときだけ**。他はすべて Idle (pill) 止まりで、開くのはユーザー | 
| **取り消し猶予は押しのけられない** | 猶予中に別のアクティビティが来ても、猶予の行は消えない (期限が来るまで) |
| **dismiss できる** | どのアクティビティも払える。同じ種類を「今後出さない」にでき、その設定は残る |

**受け入れ基準**: 5 種類のアクティビティを同時に発生させても、Idle の高さが変わらず、取りこぼしも重なりも起きない。

### 3.8 プライバシー

普段は何も出ていないので、**漏れるのは「開いたとき」**です。そして画面共有中は**開く**: 共有相手に渡す
ファイルを探す、さっきコピーしたものを貼る — 共有の最中こそ、シェルフとクリップに手が伸びる時間です。
しかも notch はどのアプリよりも手前に出るので、共有しているウィンドウを選んでいても一緒に映ります。
「普段は出ていないから安全」ではなく、**出る瞬間が共有中に重なる**という形の事故になります。

| 規則 | 内容 |
|------|------|
| **既定は「存在」だけ、「中身」は出さない** | Idle はシェルフの**件数**とアクティビティの**種類**まで。ファイル名・クリップ本文はホバー / Open で初めて出る |
| **共有中は伏せる** | 画面共有・録画・ミラーリングを検出したら、ホバーしても中身を出さない (件数のみ)。検出手段は要調査 (R15) |
| **手動のプレゼンモード** | 検出できない環境のための明示スイッチ。launcher のコマンドからも切り替えられる |
| **Focus 連動** | OS の集中モード中は pill を抑制する (既定オン) |

**受け入れ基準**: プレゼンモードで、シェルフ 5 件 + クリップ 10 件を保持したまま画面共有しても、
ファイル名・クリップ本文が 1 文字も画面に出ない。

### 3.9 プラグインが載せるもの

[§3.0](#30-判断基準) の T4 で落ちたもの (メディア・天気・統計・CI 監視・ポモドーロ) は、**要らないのではなく、
コアが持つべきでない**というだけです。置き場所を plugin にします。これで「ウィジェットホストにしない」と
「ウィジェットが欲しい」が両立します。

> **これは置き場所の方針であって、動作の保証ではありません。** plugin が実際にそれを作れるかは、
> ① その情報を**公開 API で取れるか** (Now Playing は取れない可能性がある — R7)、② host が
> その capability を plugin に渡すか、の 2 つに依存します。現時点で `notch` interface にメディアや
> 音量を読む手段はありません。「コアでは作らない」と「plugin なら作れる」は別の主張で、
> 後者はまだ未確定です。天気や CI のように**ネットワークから取るもの**は既存の `network` 権限で足りるので、
> この不確かさは OS の状態を読む種類のものに限られます。

plugin が寄与できるのは 3 種類:

| 種類 | 内容 | 制限 |
|------|------|------|
| **activity** | 1 行のアクティビティを投げる (進捗つき可) | 権限 `notch`。**1 plugin あたり 3 件/分**、超過は静かに drop。優先度は常に最下位 (④) |
| **shelf action** | シェルフの選択に対するアクションを足す (例: 「画像を圧縮」「Gist にアップロード」) | 実行は既存の権限モデルに従う |
| **widget** | Open したときだけ描画される小さいカード | **開いている間しか更新されない**。閉じている間にタイマーを回す手段は与えない |

widget が「開いている間だけ」なのが要点です。これが無いと、notch は**常駐ポーリングの集積所**になり、
アイドル CPU 0 という予算 ([§6](#6-非機能要件)) が初日で崩れます。

描画は plugin API と同じ「データを返させて、描画はホストが行う」モデル
([`plugin-api.md`](./plugin-api.md) §4) に乗せ、`view-node` を使い回します。WIT の `notch` interface
(`push-activity` / `update-activity` / `resolve-activity` と、export の `render-widget`) は
**P5 で [`plugin-api.md`](./plugin-api.md) に追加する**もので、まだ存在しません。

### 3.10 コアに載せないもの

| 項目 | 落ちたテスト | 置き場所 |
|------|------------|---------|
| Now Playing (再生中 + 操作) | **T4** — Control Center が同じものを 20px 隣で出している。加えて macOS の `MediaRemote` は非公開 API (R7) | plugin (R7 次第。取れなければ誰も作れない) |
| 音量・輝度 HUD の置換 | **T4** — OS の HUD を消す公開手段が無く、消せないなら**二重に出る**だけ | plugin (同上) |
| バッテリー / 充電 | T2, T4 — 見た後にできることが無く、メニューバーに出ている | plugin |
| カレンダーの次の予定 | T3, T4 — 常設表示。EventKit 権限まで取って席を占める価値がない | plugin |
| システム統計 (CPU / メモリ / ネット / GPU) | T1, T2 — pull のものを push の席に置いている。常時ポーリングも要る | plugin |
| 通知のインライン返信 / 音声返信 | 通知の傍受は macOS に公開 API が無く、権限も重い | **作らない** |
| カメラミラー / ポモドーロ / 健康系 | Launcher × Explorer の軸から遠い | plugin |
| CI / PR 監視 | 同上 | plugin (`nohrs-plugin-git` 系) |
| テーマ / GIF / 触覚フィードバックの作り込み | — | P5 のテーマ機構に相乗りする範囲に留める |

## 4. ジェスチャとキー

| 操作 | 動作 |
|------|------|
| ホバー | Idle → Hover |
| クリック | Open (最後に見ていたタブ) |
| ファイルをドラッグして上端へ | Open (シェルフタブ) |
| 下スワイプ / 二本指スクロール↓ | Open |
| 上スワイプ | Close |
| `Cmd+Shift+B` (既定、変更可) | Open / Close トグル |
| `Esc` | Close |
| `Tab` / `Shift+Tab` | タブ切り替え |
| `1`-`9` | クリップ / シェルフの n 番目を実行 |

ホットキーは launcher と**同じホットキーレジストリ**を使います ([`launcher-requirements.md`](./launcher-requirements.md) §7.2)。

既定が `Cmd+Shift+B` なのは、`Cmd+Shift+N` が explorer の「新規フォルダ」
([`explorer-essentials.md`](./explorer-essentials.md) §6) だからです。notch のトグルは**グローバル**登録なので、
アプリ内キーマップと重なると explorer が前面のときに両方が走ります。既定値を選ぶときは §7.2 の衝突検出を
アプリ内キーマップに対しても通すこと — レジストリがグローバル同士の衝突しか見ないなら、この種の事故は防げません。

## 5. 実装方式

### 5.1 ウィンドウ

| 観点 | macOS | Linux |
|------|-------|-------|
| ウィンドウ種別 | `NSPanel` + `.nonactivatingPanel` (フォーカスを奪わない) | X11: override-redirect / `_NET_WM_WINDOW_TYPE_DOCK`。Wayland: `wlr-layer-shell` の `top` レイヤ |
| レベル | `.floating` 以上 (メニューバーより上) | `_NET_WM_STATE_ABOVE` |
| スペース | `.canJoinAllSpaces` + `.fullScreenAuxiliary` (全画面アプリの上でも出る) | コンポジタ依存 |
| 背景 | 透過 + 角丸。notch の「黒」と継ぎ目なく繋ぐ | 同左 (コンポジタが無ければ不透明) |
| 入力 | Open 時のみクリックを受ける。Idle / Hover 時は**ホバー判定のみ**でクリックは透過させたい | 同左 |

**重要な未解決点 (R1)**: gpui 0.2 の `WindowOptions` は `window_bounds` / `kind` (`Normal` / `PopUp` / `Floating`) /
`window_background` / `window_decorations` を持ちますが、**ウィンドウレベルの直接指定・非アクティブ化パネル・
クリック透過・全スペース表示の公開 API は見当たりません**。launcher も同じ制約を受けていて、
「Wayland の activation token を渡せない」問題が既に出ています ([`launcher.md`](./launcher.md) §13)。

取り得る道は 3 つ:

| 案 | 内容 | 評価 |
|----|------|------|
| **A** | gpui に upstream で API を足す (`WindowOptions::level`, `nonactivating`, `mouse_passthrough`) | 本筋。ROADMAP Future Work の「GPUI コミュニティへの貢献」と整合。ただしマージ待ちが読めない |
| **B** | `nohrs-platform` ([`launcher-requirements.md`](./launcher-requirements.md) §7.3) から、gpui が作った `NSWindow` を取得して属性を後付けする | 実現可能だが gpui 内部表現に依存し、版上げで壊れる |
| **C** | notch 専用ウィンドウだけ gpui の外で作る | 描画基盤が二重になる。却下 |

**推奨は A を目標に B で先行**。B のコードは `nohrs-platform` の 1 モジュールに閉じ込め、
「gpui に API が入ったら消す」ことを doc comment に明記する。

### 5.2 notch の幾何

- macOS: `NSScreen.safeAreaInsets.top > 0` で notch の有無を判定し、`auxiliaryTopLeftArea` /
  `auxiliaryTopRightArea` から notch の幅・高さを求める (機種ごとの数値をハードコードしない)。
- ディスプレイ構成変更 (外部接続 / 解像度変更 / スケーリング変更) を監視して再配置する。
- 内蔵ディスプレイが閉じている (クラムシェル) ときは、フォールバックの浮遊バーに切り替える。
- どのディスプレイに出すかは設定 (既定: 内蔵 → 無ければメインディスプレイ)。

### 5.3 crate 配置

```text
crates/nohrs-notch/          # 新規 (D6)
├── src/nohrs_notch.rs       # サーフェスのライフサイクル、状態機械
├── src/window.rs            # ウィンドウ生成・幾何・ディスプレイ追従
├── src/shelf.rs             # シェルフのモデル (ビューは nohrs-ui)
└── src/activity.rs          # ライブアクティビティの購読
```

依存は `nohrs-ui` / `nohrs-services` / `nohrs-store` / `nohrs-platform` / `nohrs-core` の下向きのみ。
**`nohrs-launcher` と `nohrs-pages` は参照しません** ([`architecture.md`](./architecture.md) §2 の依存ルール)。
共有するのはコマンドレジストリ (`services::command`) と UI コンポーネント (`nohrs-ui`) だけです。

### 5.4 ライブアクティビティの購読

進捗は「ファイル操作サービスが `Progress` イベントを流し、notch が購読する」形にします。
explorer も同じイベントを購読して自分のステータスバーを更新するので、**進捗の実装は 1 つ**で済みます。

```text
services::fs::ops  ──(async-channel / postage broadcast)──┬──▶ pages::explorer  (ステータスバー)
                                                          └──▶ notch::activity  (ライブアクティビティ)
```

## 6. 非機能要件

| 観点 | 予算 |
|------|------|
| Idle (アクティビティ無し) の CPU | **0%** (タイマーを回さない。イベント駆動のみ) |
| Hover → 描画 | < 50ms |
| ドラッグ検知 → Open | < 150ms |
| 追加 RSS | < 25MB (シェルフのサムネイル込み) |
| ディスプレイ構成変更への追従 | < 1s |
| 画面収録権限 | **不要**。必要になる機能は作らない |
| フルスクリーン動画の上に出る | 出せること。ただし**動画再生中は Idle を抑制**する設定を持つ |

## 7. 設定 (`config.toml` 追加分)

```toml
[notch]
enabled = true
display = "builtin"        # "builtin" | "main" | "all"
fallback_bar = true        # notch が無い環境で浮遊バーを出すか
idle_indicator = true      # Idle (pill) を出すか
open_on_drag = true        # ドラッグで上端に近づけたら開くか
hotkey = "Cmd+Shift+B"

[notch.tabs]
shelf = true
clipboard = true
activity = true
widgets = false            # plugin 提供のウィジェット (§3.9)。P5

[notch.privacy]
# 既定は「存在」だけを出し、「中身」はホバー / Open で初めて出す (§3.8)。
presentation_mode = false  # 手動。オンの間はホバーしても中身を出さない
hide_when_shared  = true   # 画面共有・録画・ミラーリングを検出したら伏せる (R15)
suppress_in_focus = true   # OS の集中モード中は pill を抑制する

[notch.watch]
# 見張り (§3.5)。ユーザーのフォルダを覗く 2 つは既定オフ。
downloads       = false    # 新着ダウンロードを一定時間だけ取り出せる状態に置く
downloads_ttl_minutes = 10
screenshots     = false    # 撮った直後のスクリーンショットを出す
volumes         = true     # マウント / 取り外し (取り外しは進行中の操作があるときだけ警告)
low_disk        = true     # コピー先の空きが足りないときだけ

[notch.activity]
undo_grace_seconds = 10    # 破壊的操作の取り消し猶予 (§3.4)。0 で無効

[notch.shelf]
persist = true             # 再起動を跨いで復元するか
max_items = 100
```

## 8. フェーズ割当

| Phase | 範囲 |
|-------|------|
| **P4** | サーフェス基盤 (状態機械・ウィンドウ・幾何・フォールバック) / シェルフ (§3.2) と `noh shelf` CLI / ドロップ先ファンアウト (§3.3) / ライブアクティビティ + 取り消し猶予 + 失敗の回収 (§3.4) / クリップボード覗き見 (§3.6) / アービトレーション (§3.7) / プライバシー既定 (§3.8) / 設定 |
| **P5** | 見張り (§3.5) / plugin の寄与 3 種と WIT `notch` interface、plugin が投げるアクティビティ (§3.9) / テーマ連携 |
| **P6** | 性能ゲート (Idle CPU 0%) の CI 計測 / Linux の対応状況マトリクス確定 |

**P4 に §3.7 と §3.8 を入れてあるのは後回しにできないため**です。アービトレーションは
「2 つ目のアクティビティが来た日」に必要になり、後から入れると表示の作りを作り直します。
プライバシーの既定 (中身を出さない) は、後から変えると**それまでのユーザーが既に画面共有で漏らした後**です。
